## 0. INSTRUMENTS, AND WHAT WAS CHECKED BEFORE ANYTHING WAS BELIEVED

Both instruments were **reused verbatim**, not rewritten.

**A. `ringtime.py` carries its own mirror control by construction.** It computes
the two teams **identically** — every socket number below has the opponent's
own value in the same row, from the same walk of the same turn stream. A
plank-side artefact would have to move both columns.

**B. Internal consistency check on the seal logic, run before reading it.**
`seal_r` fires only when a team has zero free and zero own-relay sockets, so
`plugmax == 8` (all 8 held by the enemy) **must** imply `seal_r >= 0`, and
`plugmax < 8` with a free socket must imply `seal_r == -1`.
**MEASURED: 6 of 6 games with `plugmax == 8` have `seal_r >= 0`; 0 of the 19
games with `plugmax < 8` are sealed with a free socket outstanding.** The two
columns are computed independently in the loop; they agree 25/25.

**C. Seat mapping is engine-side, per match, not assumed.** Read from each
`.meta.json`: we are **team B** in `20a19adb` and **team A** in the other four.
The join asserts this per file rather than defaulting.

**D. The claim column is the crater study's own definition, unmodified.** A
"socket" = one of the **8 tiles orthogonally adjacent to a team's 2×2 core
footprint**. `own1_r` = the round that team first stands a friendly
conveyor/splitter on one of its 8; **`-1` encodes NEVER**, and the share of
`-1` rows is the crater study's `never-claims-a-socket %` instrument verbatim.

**E. The core-damage ledger self-checks, and did. MEASURED: 50 of 50 ledgers
(25 games × both cores) report `MATCH`, 0 `MISMATCH`.** `replay_autopsy.py`
requires attributed damage per source to equal the summed `UpdateHp` deltas on
the core id, and says so rather than reporting the pretty number when they
disagree.

**F. ⭐ TWO-CLOCK MAP IDENTIFICATION — and both clocks were built before either
was read.** Replays carry terrain but no map name. Two independent routes were
run and only then compared:
1. **Platform-side**: `fcode match info <id> --json` returns a per-game
   `mapName` (and `mapSeed`) — the organisers' own label.
2. **Replay-side**: terrain fingerprint of each replay against the 34
   distinct-content maps under `maps/` (57 files, deduplicated by md5) under all
   8 dihedral transforms, via `tools/replay_census.Replay` +
   `tools/map_encode.parse_map26`, with a uniqueness control.

**MEASURED: 20 of 20 agreement, 0 mismatches** on the games available when the
fingerprint ran, joined on (match id, game number) and diffed row by row. The fingerprint's own control was clean
independently (0 unmatched, 0 cross-name ambiguity; multi-transform matches
occur but always resolve to the *same* name, i.e. map self-symmetry).
**This matters beyond convenience: it is the first time in this repo that map
identity on a platform replay has been established by two mutually blind
methods, so neither the platform label nor the fingerprinter is now a single
point of failure for any per-map cut.**

**G. Outcome cross-check.** The replay-side `winner` field and the platform's
`winnerId`-vs-seat agree in **25 of 25** games. A seat-mapping error — the most
likely way this whole document could be silently inverted — would break this.

⚠ **THE ONE CONTROL THIS READ CANNOT RUN, STATED UP FRONT.** There is **no
v536 field arm** — v174 is the only version on this tape. The comparison
baseline is **LOCAL SELF-PLAY vs v169** (the crater study), on a **different
fixture and a different opponent set**. So the claim-round result below is a
**transfer observation**, not a controlled contrast. It is worth reading anyway
only because the moved quantity is a **bot-side behaviour with a hard floor**
(you either place the conveyor or you do not) rather than an outcome — see §1.
