# v141 "Counter Router v1" — identification (read-only, no verdict)

Downloaded via `.venv/bin/fcode submission download 141` -> `scratchpad/x3r0_v141/v141.zip`,
unzipped to `scratchpad/x3r0_v141/v141/`.

## Files in v141

l_doctrine.py, l_eco.py, l_main.py, l_raid.py,
m_doctrine.py, m_eco.py, m_main.py, m_raid.py,
main.py, README.md

Two-policy MoE router (same shape as v137): top-level `main.py` decides,
per-unit, whether to instantiate `l_main.Player()` or `m_main.Player()` based
on a terrain fingerprint. `l_*` and `m_*` are isolated module namespaces
(each policy imports only its own prefix) so doctrine globals in one policy
cannot leak into the other inside a unit subinterpreter — same isolation
rationale v137 used with `b_*`/`c_*`.

## Routing logic (quoted from `main.py`)

```python
WEAK_KEYS = {
    (25, 25, 5, 5, 18, 18),   # drumlin
    (20, 26, 2, 2, 2, 22),    # nordkap
    (30, 30, 14, 2, 14, 26),  # glacierkeep
}
```
— identical set/values to v137's `WEAK_KEYS`.

Dispatch (`Player.run`): on first call per unit, locate own core (falls back
to a stored enemy-core-derived guess, else defaults to `l_main.Player()` if
the core can't be found at all — "the first builders always see home; this
fallback mainly protects an exotic engine ordering and stays on v135"),
decode the map's known terrain grid, and:

```python
self.inner = m_main.Player() if grid in WEAK_GRIDS else l_main.Player()
```

`WEAK_GRIDS` is built by decoding `l_doctrine.MAP_CODES`/`EXTRA_MAP_CODES`
entries whose key is in `WEAK_KEYS` (plus a hardcoded yulerune/frostgate
shared-prefix special case) into terrain-grid tuples via
`_decode_grid` (ternary ALPHABET-indexed run-length-ish decode, `.#o` for
empty/wall/ore). So: **default policy = `l_main` (v135/ECORAID-line
chassis); on drumlin/nordkap/glacierkeep (+ the yulerune-as-frostgate
special case) = `m_main` (v134-line chassis).** Identical map-keyed routing
to v137; only the module prefixes changed.

## New/changed logic vs v137: fixed spawn-salt table

Both `l_main.py` and `m_main.py` replace v137's randomized noise:
```python
import random
self.spawn_salt = random.Random().randrange(97) if NOISE_ON else 0
```
with an **identical** fixed FNV-1a(-style)-keyed lookup, same 15-entry dict
in both files:
```python
sig = 2166136261
for ch in "|".join(self.map_grid):
    sig = ((sig ^ ord(ch)) * 16777619) & 0xFFFFFFFF
self.spawn_salt = {
    2024030065: 0,   # antler
    1742285299: 0,   # archipelago
    2251200169: 89,  # auroraveil
    2959488499: 0,   # drakkarfjord
    2309041557: 31,  # drumlin
    4055986179: 0,   # fjordgate
    1941512695: 73,  # frostgate
    446389448: 7,    # glacierkeep
    1691756395: 31,  # icefloe
    999493859: 43,   # midgard
    3103780539: 19,  # nordkap
    1715578931: 0,   # ragnarok
    733716547: 73,   # royale
    998525177: 0,    # valkyrie
    3313952939: 43,  # yulerune
}.get(sig, 0)
```
(FNV-1a 32-bit: offset basis 2166136261, prime 16777619.) `NOISE_ON` is
still defined (`= False` in both `l_doctrine.py`/`m_doctrine.py`) but is no
longer referenced anywhere — vestigial, zero behavioral effect now that the
salt path is a fixed table rather than a `NOISE_ON`-gated random draw.

## Anomaly / notable observations

1. **Vestigial dead flag**: `NOISE_ON` is defined (`False`) in both doctrine
   modules but has zero remaining references now that spawn_salt is a fixed
   table — a leftover from the v137 random-noise code path that the salt-table
   patch didn't clean up.
2. **Encoding artifact, not a content diff**: several comment lines that
   contain non-ASCII punctuation (`≈`, `—`, `⇒`, `⚠`) come through in v141 as
   mojibake (`â‰ˆ`, `â€”`, `â‡’`, `âš `) versus clean UTF-8 in the v137/v134/v135
   comparison trees on disk. Same byte content misdecoded, not an edited
   comment — flagged so it isn't miscounted as a real change in any diff line
   count above.
3. **Same fixed-salt table shared by both policies**: the FNV-1a lookup table
   is byte-identical between `l_main.py` and `m_main.py` — a single
   terrain-keyed table serves both chassis, consistent with the README's
   "Keep both policy branches on the same terrain-only opening" comment
   inside `m_main.py`.
4. **README's provenance section (`counter_router_v1_screen_fixed`,
   `_confirm`, `_tle10`) references named test-run artifacts not present in
   this download** — those are presumably local test-harness run names, not
   files shipped in the submission zip.
