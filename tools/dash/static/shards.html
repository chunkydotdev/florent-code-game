Fleet boxes

Each host's own generated worklist (scratchpad/vps/<host>/worklist.txt) joined to its pulled artefacts — so remote-only shards get a real state and the queue on the box is visible, which no local surface shows. Every age here is an age at last pull (vps_pull, 5-min cadence); the pull age is printed per host because when the pull is old, that is the louder fact. A heartbeat that says RUNNING but stopped being written renders STALLED — on this fleet that is what a dead fossil looks like, and it is not the same thing as running.

Artefacts with no worklist line

corefill_status.sh iterates the worklist, so these shards — whose lines were replaced by later batches — are not covered by the authority. This page therefore prints no state, no rows and no rate for them; only the artefacts they left on disk. Deriving those numbers here would be a second copy of the computation, which is the one thing this view is not allowed to be.

How to read this table

Every state, row count, percentage, rate and band here is read out of tools/corefill_status.sh, not recomputed. tools/dash/shard_diffcheck.py re-parses the same text with a different implementation and fails on any disagreement. The words below are that tool's own, so this legend cannot drift away from what the numbers mean.
What you seeWhat it means, in the tool's own terms
running An overnight.sh <SHARD> process is alive and its heartbeat file is moving.
remote Running on a FLEET BOX (the @host badge names it), certified by its own NULLHOST calibration before any row counts. Rows arrive via vps_pull; the heartbeat age shown is the pull age, suffixed (pull). A completed remote shard leaves the tool's table and its artefacts appear in the no-worklist-line section below, host-labeled.
STALLED “alive but frozen” — the process exists, the heartbeat has not been rewritten for over 600 s.
DEAD “started, no process” — it was launched and is gone. corefill deliberately never relaunches, so it stays dead until a human looks.
DONE Its .COMPLETE marker exists: it reached its pre-registered target.
CANCELLED Someone cut it short (scratchpad/corefill_cancel/<SHARD>). Rows are KEPT, so a cancelled shard still shows the rate its partial rows give — read the progress column beside it.
queued A line in the worklist that has never been launched.
52.11% Share of that shard's finished games won by the treatment tree (the tool counts rows whose winner column is T). 50% is the no-difference point; the control is the other tree on the same line.
± 1.33pp 95% band, 1.96·√(0.25/n)·100. separated means the whole interval sits off 50 at this instant on a continuously-watched stream — suggestive, never a verdict: with continuous looks the naive interval pokes past 50 far more often than 5%, which is why verdicts happen only at the pre-registered looks (audit M1). inside band means it is not yet distinguishable from its control, which is no information, not no effect.
n<400 The tool refuses to print a rate below ~400 rows: “at n=200 the 95% band is about ±7pp; a number printed there reads as a result and is noise”. This page inherits the refusal instead of putting a tempting number beside n=41.
RETIRED 50% Half this shard's rows were played on maps that have left the live pool (the 2026-08-13 rotation retired 4 of the old 8 battery maps). Its rate spans dead geometry and must not be pooled with a live-pool shard's.
RETIRED: BLIND The live pool could not be parsed out of tools/overnight.sh, so the tool cannot tell how much of this rate is dead geometry. Not the same as zero.
